# 🛡️ Financial Fraud Detection Dashboard

An end-to-end data analytics project that detects fraudulent credit-card
transactions using Machine Learning and presents the results in an
interactive **Streamlit** dashboard.

Built for: *Financial Fraud Detection Model (Data Analytics)* college project.

---

## 🧠 What the project does

1. **Data preprocessing** — cleans the raw transaction data, parses dates,
   encodes categorical fields (transaction type, location).
2. **Feature engineering** — builds day/month/weekday/weekend features and
   a leakage-safe "historical fraud rate" signal per merchant and per
   location (computed only from the training split).
3. **Model training** — trains two classifiers with class-balanced weighting
   (fraud is ~1% of transactions):
   - Logistic Regression
   - Random Forest
4. **Evaluation** — ROC-AUC, precision/recall/F1, confusion matrix, ROC curve.
5. **Interactive dashboard** (`app.py`) with four pages:
   - **📊 Overview** — KPIs, transaction/fraud trends over time, amount distribution
   - **🔍 Fraud Analytics** — fraud hotspot map, fraud rate by city/weekday, riskiest merchants
   - **🤖 Model Performance** — confusion matrix, ROC curve, model comparison table
   - **⚡ Live Prediction** — score a hypothetical transaction in real time with a risk gauge

## ⚙️ How to run it locally

### 1. Clone your repo and set up a virtual environment
```bash
git clone https://github.com/<your-username>/fraud-detection-dashboard.git
cd fraud-detection-dashboard
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
```

### 2. Install dependencies
```bash
pip install -r requirements.txt
```

### 3. Train the model (creates the `models/` folder)
```bash
python src/train_model.py
```
You should see output like:
```
Logistic Regression: ROC-AUC = 0.4887
Random Forest: ROC-AUC = 0.5044
```

### 4. Launch the dashboard
```bash
streamlit run app.py
```
It will open automatically at `http://localhost:8501`.

## 📊 About the dataset & an honest note on model performance

The dataset (`credit_card_fraud_dataset.csv`, 100,000 transactions) labels
about 1% of transactions as fraud. During evaluation, this project found
that the fraud label in this particular sample dataset **does not
meaningfully correlate with any of the provided columns** (amount,
location, merchant, transaction type, day of week) — you can verify this
yourself in the "Fraud Analytics" tab, where fraud rate barely changes
across any slice of the data.

This is flagged transparently inside the **Model Performance** tab of the
dashboard rather than hidden. It's a realistic and valuable finding for a
data analytics project: it demonstrates the ability to evaluate a model
honestly, instead of reporting a misleadingly high accuracy (predicting
"not fraud" for every transaction would already score ~99% accuracy on
this imbalanced data — which is exactly why this project reports
precision/recall/ROC-AUC instead of accuracy).

If you have a richer dataset — e.g. `financial_fraud_detection_dataset.csv`
or `synthetic_fraud_dataset1.csv` with fields like transaction velocity,
device ID, or customer spending history — you can swap it in:
1. Replace the file in `data/`
2. Update the `load_data()` path and `FEATURE_COLS` list in `src/train_model.py`
3. Re-run `python src/train_model.py`
4. The dashboard picks up the new model automatically

## 🚀 Deploying to GitHub + Streamlit Community Cloud

### Step 1 — Push to GitHub
```bash
cd fraud-dashboard
git init
git add .
git commit -m "Initial commit: fraud detection dashboard"
git branch -M main
git remote add origin https://github.com/<your-username>/fraud-detection-dashboard.git
git push -u origin main
```
(Create the empty repo first on github.com → "New repository" → don't
initialize with a README since you already have one.)

> **Important:** make sure you run `python src/train_model.py` and commit
> the generated `models/` folder too, since the dashboard loads the `.pkl`
> files directly — it does not retrain on every visit.

### Step 2 — Deploy on Streamlit Community Cloud (free)
1. Go to **[share.streamlit.io](https://share.streamlit.io)** and sign in with GitHub.
2. Click **"New app"**.
3. Select your repository, branch (`main`), and set **Main file path** to `app.py`.
4. Click **Deploy**.
5. Streamlit Cloud installs `requirements.txt` automatically and gives you a
   public URL like `https://your-app-name.streamlit.app` — this is what you
   submit for your project.

If the deploy fails, check the app logs on Streamlit Cloud — the most common
issue is a missing package in `requirements.txt` or forgetting to commit the
`models/` folder.
